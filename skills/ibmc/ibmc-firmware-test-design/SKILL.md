# iBMC 与固件安全测试设计

先读取 [共享约定](../contract.md)；公开分类见 [来源说明](../sources.md)。

## 输入

型号/板卡修订、固件版本、合法获取的镜像与来源摘要、更新说明、权限表、启动设计与恢复方案。没有固件材料仍可规划验证，但不能报告二进制分析结果。

## 方法选择

| method_id | 设计重点 | 必要证据与判据 |
| --- | --- | --- |
| FW-INVENTORY | 将组件名称、实际构建版本、补丁记录与固件摘要绑定；密钥线索脱敏定位 | 缺精确版本/补丁证据时只保留适用性线索；版本字符串不直接确认可利用性 |
| FW-UPDATE-AUTHZ | 分开读取更新信息与提交更新；对照角色及接口路径 | 响应、任务、版本/配置与审计；低权限拒绝应无非预期状态变化 |
| FW-INTEGRITY | 已批准样机上设计合法包对照与非可信/损坏包拒绝验证 | 包来源摘要、校验结果、写入前后状态；拒绝异常包不能单独证明启动链完整 |
| FW-ROLLBACK | 先确认版本回退策略和允许的例外，再设计对应版本组合 | 版本策略、安装结果、日志；允许的维护回退不是自动判为漏洞 |
| FW-RECOVERY | 依据已批准故障注入方式验证失败更新的可恢复性 | 状态、恢复过程、业务健康与版本；没有旁路恢复条件时阻塞故障注入设计的执行准入 |
| FW-BOOT-TRUST | 分清更新校验与启动执行阶段的信任依据 | 需要启动链相关设计及实际证据；只有远程 API 记录时结论保持证据不足 |

## 工作与输出

按模块、风险路径及正式要求选择方法，生成共享约定格式的 test-cases。管理协议只依据实际文档建入口；远程控制、电源控制、虚拟介质、日志/配置和维护操作关注各自的角色与业务影响，不把 Web 权限结果推广到所有协议。

每例说明正常对照、异常输入类别、观测点、通过/失败/证据不足判据。固件写入、回退、故障注入与重启明确要求隔离样机、备份、旁路恢复、批准窗口和停止阈值；设计中保留未批准状态。本包不刷写、不提取真实密钥、不访问调试口。
