# 风险模块与攻击路径规划

先读取 [共享约定](../contract.md)。采用 [来源说明](../sources.md) 中的测试分类，风险优先级是本项目判断。

## 输入

产品清单、暴露面记录、测试目标和人员已确认的范围。保留人工规划项；AI 新建议单独标为待确认。

## 工作过程

1. 从可达身份、输入可控程度、跨权限操作、业务影响和现有防护证据解释优先级。不能只按漏洞名称分级，也不以缺文档直接判定高危漏洞。
2. 为模块建立风险记录：可能影响、入口、成立条件、支持与反对证据、未知变量、建议优先级、人工取舍。
3. 路径按“起始身份 → 入口 → 行为/权限边界 → 目标资源”展开。每一步写前提、source_ids、待验证的问题和 candidate/supported/contradicted/unknown 状态。
4. 选择适用方法：URL 服务端获取关联 SSRF；不可信内容展示关联 XSS；对象/动作授权关联越权；更新包关联固件方法。没有适用入口的方法标待定或不适用，不强制套满。
5. 把可独立验证的边界拆成用例建议。保留可否定路径的正常对照，记录未纳入范围的原因；只有全部必要步骤有证据才能确认整条路径。

## 输出与检查

输出 risk-and-path-plan：风险模块表、路径表、建议 method_ids、拟设计用例、未覆盖项和人工确认点。路径不以成功攻击叙述；漏洞挖掘中新线索应产生路径修订，不能覆盖旧执行记录。
