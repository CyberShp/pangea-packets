# Web/API 测试设计

先读取 [共享约定](../contract.md) 和 [方法表](references/methods.md)。来源定位见 [来源说明](../sources.md)。

## 输入与设计

输入模块/接口资料、角色表、候选路径、适用要求和环境约束。选择方法前确认触发条件；找不到接口或安全要求时先形成补充资料任务。

每个用例落实到产品版本、具体入口、角色、正常对照、单个验证问题。将通用方法展开为“准备 → 操作 → 响应及状态观察 → 判定 → 恢复”，填写共享约定的全部用例字段。正常与异常操作使用同条件比较，每次只改变与目标相关的因素。

安规用例关联已确认的要求版本和条目；渗透用例关联候选路径及方法，可共用证据但分别解释结论。没有正式条目时不得虚构 SEC 编号或宣称满足安规。

设计阶段不发送请求、不生成或运行自主攻击脚本。验证输入采用无害标记、测试账户、测试文件和受控接收端；若需更高影响操作，描述所需授权与观测，不假定已获批准。

## 输出与检查

输出 test-cases，并给出方法适用性矩阵。响应码、回显、时间差分别只是证据的一部分；写清需要何种后端状态/日志才能支持失败判定。前提不明、来源冲突或恢复未落实的用例保持 draft。设计完成不修改执行状态 not_run。
