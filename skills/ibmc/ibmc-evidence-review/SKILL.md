# 证据分析与复测

先读取 [共享约定](../contract.md)，方法来源见 [来源说明](../sources.md)。

## 输入与过程

1. 读取用例及修订、实际环境、执行记录、原始证据。缺执行记录时结果为 not_run，不能从设计推测通过。
2. 校对时间、目标、身份、输入与任务关联。来自另一版本或角色的证据另列；脱敏不能删除影响判定的关联字段。
3. 对比正常对照、异常响应、状态变化与审计。响应 403 而发生受保护状态变化时保留冲突；关联证据完整则按判据失败，关联不清则 inconclusive。
4. 独立标记执行故障和产品行为。工具崩溃、无响应、日志丢失不等于漏洞。失败用例也可能只是功能问题；报告漏洞需描述被突破的安全边界和证据，不自动给严重性分数。
5. 按路径逐步更新证据状态。单步成立不能证明更长链条；新线索生成候选路径/补充用例，不篡改原用例以迁就结果。
6. 复测冻结原始证据，记录新版本和变更点，重放必要条件与正常对照；修复一个入口后，其他未测入口仍未知。恢复失败单独报告，即使用例安全判据通过也不能标为恢复完成。

## 输出

输出 results-and-retest：逐例判定及理由、证据引用、漏洞/线索记录、路径状态、恢复情况、复测条件、未覆盖与阻塞项。结论可复核但不凭空补日志；只有设计或模拟记录时必须在标题和结论标明。
