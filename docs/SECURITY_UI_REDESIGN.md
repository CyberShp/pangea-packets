# iBMC 安全测试 UI / UX 改造

## 页面与交互

使用已确认的浅色、青绿主色设计，平台首页保留两个应用入口。iBMC 页面采用固定项目导航、明确的下一步入口，以及列表 / 详情布局。

- 平台首页、项目列表、项目工作台。
- 信息收集、风险与范围、攻击路径、测试用例。
- 执行与挖掘、结果与复测、方法与 Skills。
- 新建项目、添加资料、审查用例、证据详情；其他编辑操作复用表单弹窗。
- 1440 / 1024 / 390 宽度适配；移动端项目导航横向滚动，表格局部滚动。
- 原生 dialog 提供焦点约束、Escape 关闭和触发点焦点恢复。

## 数据与行为

继续使用 `pangea.ibmc.demo.v1`，兼容现有记录，未重新初始化用户数据。新增字段均可选：项目测试目标、资料来源、路径资料关联、最近审查意见与时间。

修改用例、路径或关联风险范围会撤销相关用例的已审查状态；已创建批次使用独立快照，不被后续编辑修改。创建批次仅纳入已审查且所属风险在范围内的用例；复测还需匹配原批次用例。

资料仍由人工记录。内置方法直接读取仓库 Skill 文本。iBMC 未接入 AI 或真实设备执行，界面明确区分模拟状态与真实测试结论。证据详情显示记录和缺口，不伪造设备日志、通过率或漏洞结果。

异常报文应用保留原组件与 API。应用切换时保留已挂载组件，平台样式不包裹报文工作台。

本地存储读写错误不会覆盖旧数据；保存失败时表单保持打开。当前审查记录仅保留最近一次意见，不是多用户审计历史。

## 验证

- `npm ci`、`npm run build`：通过。
- 完整浏览器流程：新建项目 → 资料 → 风险 → 路径 → 草稿 → 退回 / 确认审查 → 模拟批次 → 证据 → 修改撤销审查 → 复测 → 刷新恢复。
- 核对批次快照与编辑后的用例独立；未审查用例不能进入复测。
- 8 个项目页面 × 1440 / 1024 / 390 宽度：无页面级横向溢出。
- 损坏数据保护、表单保存失败不关闭、Escape 关闭抽屉、应用切换、异常报文深色主题隔离。
- 浏览器未发现 pageerror。报文 API 在本次 UI 验证中使用空列表替身；未运行真实 SSH、报文发送或设备测试。

复现：启动 `npm run dev -- --host 127.0.0.1` 后，在已安装 Playwright 的环境执行 `node scripts/security-ui-smoke.cjs`。可通过 `PLAYWRIGHT_MODULE` 指定外部 Playwright 包，`CHROMIUM_PATH` 指定已安装浏览器，`UI_BASE_URL` 指定预览地址。脚本创建独立浏览器上下文，截图写入被 Git 忽略的 `output/ui/`。
