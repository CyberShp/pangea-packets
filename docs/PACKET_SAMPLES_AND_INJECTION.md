# 报文样本与监听注入

## 使用流程

1. 在「报文样本」导入经典 PCAP，或在授权确认后从远端 Linux 网口限量抓包。
2. 从列表选择报文，修改已识别的字段，或按从 0 开始的字节偏移覆盖、插入、删除；Padding 可指定重复字节模式和总长度。
3. 默认保留字节中的长度和校验和。需要有效校验和时显式选择计算策略；按实际字节修正长度会把尾部字节计入 IP 负载。
4. 保存用户模板，再从场景的模板列表添加报文；也可直接添加当前编辑报文。保存场景后导出或配置执行。
5. 监听模式选择匹配位置、触发条件、序号推导、地址映射及校验和策略。保存并校验后，核对授权范围再执行。
6. 执行日志记录触发报文和成功提交给发送接口的首个报文字节；相同报文重复发送的总数以执行结束报告为准。可导出执行证据 JSON。接口提交字节不代表物理线上字节，必须结合旁路抓包检查网卡修正与填充。

## 本轮支持边界

- 导入：经典 PCAP 2.4 / Ethernet，大小端及微秒、纳秒格式；最多 16 MiB、1000 包。拒绝截断记录、损坏文件和非 Ethernet 链路。PCAPNG 须先转换。
- 远端抓包：1–30 秒、1–100 包、显式授权，使用 SSH 和远端 Scapy/libpcap；页面操作等待抓包结束。返回非 Ethernet 报文时报告失败。
- 单个原始报文：14–65535 字节。未识别协议可以原样保留并按字节编辑；字段识别与自动修正支持无 VLAN 的 Ethernet/IPv4/TCP/UDP、标准 UDP/4789 VXLAN。
- 样本以原始字节保存。传统协议模型报文可载入样本编辑器，生成当时的字节快照。原始样本不叠加传统异常规则，使用样本编辑器直接修改。
- 用户模板保存、更新、删除不改写已有场景中的报文快照；模板删除没有回收站。原始采集批次保持不变。未保存编辑在应用内切页保留，刷新前提示保存。
- 监听序号：同向复制触发包 seq/ack；反向以其 ack 作为 seq，并将实际 IP 范围内的 TCP 负载长度及 SYN/FIN 消耗计入 ack，按 32 位回绕。不将 Ethernet Padding 计入 TCP 负载。
- 注入地址可保留模板值、同向复制或反向交换；VXLAN 模式同步处理内外层地址和端口，不自动更改 VNI。
- 默认保留校验和，便于保留指定异常；修改序号或地址后可能产生额外校验和错误。自动修正要求完整首部及一致的长度，并修正内外层校验和。
- 自动推导拒绝 VLAN、分片、非 TCP、首部不完整等不支持情况。保留序号和地址且不修正校验和时，可按原始字节发送异常报文。
- 单次监听命中执行一个批次。未命中返回失败，不能判定卡件通过。没有完整 TCP 会话状态跟踪、重传/乱序管理、全量组合生成或业务健康自动判定。

## 数据保护

样本、模板、执行证据保存在本机 app-data 中。抓包与原始字节证据可能包含业务敏感内容，为保证字节可复现，二进制证据不会按主机密码字符串做替换；普通诊断文本继续遮蔽配置中的密码。限制目录访问，不要将 app-data、PCAP 或证据上传公开仓库。
