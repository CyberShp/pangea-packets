# 两个应用的页面与状态验收

基线：PR #2 已合并到 `main`。本轮沿用白色面板、浅灰背景、青绿主色、左侧导航和列表 / 详情的设计，把异常报文应用所有现有主视图纳入同一视觉体系，并补齐 iBMC 编辑与保存状态。

“帧”在此指现有产品中的可到达页面、编辑面板、弹窗及关键交互状态。下表是本次交付范围，不代表穷举所有数据、网络时序或设备状态的组合。

| 样本未保存确认    | 切换 / 恢复字节前确认；取消后保留编辑                                  |

| 执行反馈          | 等待 / 进行中 / 成功 / 失败 / 取消；连接状态、失败原因、日志           |
| 工具面板          | Hex、主机日志、校验问题、执行输出；展开 / 收起                         |

## 浏览器验收

- `npm run build`：TypeScript 与生产构建通过。
- `scripts/security-ui-smoke.cjs`：创建 → 资料 → 风险 → 路径 → 草稿 → 退回 / 确认 → 模拟执行 → 证据 → 修改撤销审查 → 复测 → 刷新。核对独立快照、审查历史、编辑放弃、并发写入拒绝、损坏记录保护。
- `scripts/packet-ui-smoke.cjs`：加载失败重试、保存失败保留草稿、协议层字段、Hex 重试、候选规则跨页保留及应用、直接 / 监听配置、校验门槛、执行确认取消 / 提交、运行进度、历史筛选、主机新增 / 连接错误恢复、网卡与 Offload 确认、样本导入 / 抓包授权、字节编辑 / 放弃 / 模板保存删除。
- iBMC 8 个项目路由 × 1440 / 1024 / 390；报文 9 个视图 × 相同宽度；新建场景弹窗及六种样本编辑状态无页面级横向溢出。宽表格和移动端导航在各自区域内滚动。
- 两套浏览器脚本均无 `pageerror`。人工核对桌面报文序列、直接配置、样本、主机、历史，以及移动端协议、监听、弹窗截图。

复现：

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
# 在另一终端，已安装 Playwright 和 Chromium 的环境中运行：
node scripts/security-ui-smoke.cjs
node scripts/packet-ui-smoke.cjs
```

脚本支持 `PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`、`UI_BASE_URL`，截图输出到忽略目录 `output/ui/`。

## 明确边界

报文浏览器测试拦截全部 API / WebSocket，验证 UI 状态与请求契约；导入使用替身响应，未验证真实 PCAP 解析，也未连接 SSH、抓取流量、修改真实网卡或发送报文。真实后端接口保持原有实现，仍需在目标测试环境做设备联调。

iBMC 仍是本地交互原型，未新增 AI 解析、多人服务端存储或真实执行。审查记录是本机历史，不是防篡改审计日志。旧的 `pangea.ibmc.demo.v1` 数据保持兼容；新增 `reviews` 为可选字段。
